# OOBB project instructions

Link catalogue names and thumbnails to the project, version or part's main README. Put the complete numbered assembly sequence and illustrations under its Assembly heading. Link the main assembly viewer to the live GitHub Pages site. Label offline copies and PDF downloads separately. Generate these destinations and written steps from the same project definitions on rebuild.

For illustrated step-by-step assembly manuals, follow [the assembly instructions guide](ASSEMBLY_INSTRUCTIONS_GUIDE.md): signature-padded books with four numbered panels per landscape A4 instruction page, cumulative CAD without arrows, quantity labels 1 mm outside each thumbnail’s lower-right edge and compact MD5-alpha typography, authored in the normal populate pipeline.

The HTML assembly viewer must default to those same four-step landscape A4 pages, starting with steps 1-4. Navigate by page and preserve the 2 x 2 grid on narrow screens with zoom/pan. Individual step images are secondary assets, not the default viewer layout.

Before creating or revising presentation renders, read the [OOBB render style guide](RENDER_STYLE.md). Apply it to renders made with this library in downstream OOBB projects as well.

For project README images, illustrated assembly instructions or repeatable presentation packages, also read [the presentation workflow](presentation/README.md) and [technical presentation style](presentation/STYLE.md). Use its AI-generated notice, verified hardware links, part manifest and render-and-review process. Preserve explicit user requirements.

For project READMEs, follow [the README guidelines](README_GUIDELINES.md). Place the project description and verified inspiration credit at the top. Explain that this is an entirely AI-generated coding project, the source is largely unreadable by humans, usable generated files are included, and publication lets others modify it with their own AI tools. The image/error notice alone does not replace this explanation. Multipart assembly projects use a versions table with an image, description, version README, hosted HTML instructions and PDF download.

For a version-five catalogue refresh, read [the catalogue refresh standard](presentation/CATALOGUE_REFRESH.md), [project rollout notes](presentation/CATALOGUE_REFRESH_PROJECTS.md) and, when a history reset is authorized, [the Git reset procedure](presentation/CATALOGUE_HISTORY_RESET.md). The refresh includes focused generator/build-code repairs, compact READMEs without file inventories, directory-based discovery, text-only navigation and canonical studio images. These documents define planned work; they do not themselves authorize changing other repositories or resetting history.

# OOBB project instructions

Before creating or revising presentation renders, read the [OOBB render style guide](RENDER_STYLE.md). Apply it to renders made with this library in downstream OOBB projects as well.

For project README images, illustrated assembly instructions or repeatable presentation packages, also read [the presentation workflow](presentation/README.md) and [technical presentation style](presentation/STYLE.md). Use its AI-generated notice, verified hardware links, part manifest and render-and-review process. Preserve explicit user requirements.

Every project Summary must explain that this is an entirely AI-generated coding project: the generated outputs are included and usually work, but the main reason for publishing is to give others a starting point for modifying the project with their own AI tools. Keep this explanation alongside the plain-English description of the object; the image/error notice alone does not replace it.

For a version-five catalogue refresh, read [the catalogue refresh standard](presentation/CATALOGUE_REFRESH.md), [project rollout notes](presentation/CATALOGUE_REFRESH_PROJECTS.md) and, when a history reset is authorized, [the Git reset procedure](presentation/CATALOGUE_HISTORY_RESET.md). The refresh includes focused generator/build-code repairs, compact READMEs without file inventories, directory-based discovery, text-only navigation and canonical studio images. These documents define planned work; they do not themselves authorize changing other repositories or resetting history.
